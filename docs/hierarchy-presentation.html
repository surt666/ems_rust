Node-formula roll-up

There is one kind of sensor. It carries a raw value series and the energy type it measures — nothing else. No main, sub, calculation or sum meters; nothing for a customer to classify. All the intelligence sits on the hierarchy node: a node's value is Σ everything below it, unless the node says otherwise. Pick an energy type and a purpose to watch the same tree answer a different question.

What changed: the formula moved off the sensors and onto the nodes, and the one mis-named axis split into two. Energy type (energitype) is what a sensor measures; it is the only thing a sensor knows. Purpose (formål) is what the energy is spent on; the node declares it, because the same sensor's kWh can be space heating here and hot water there. There is no “metric” axis: CO₂ and cost are derived from (energy_type, purpose) at read time, so the old per-sensor emission factor is gone too.
Roll-up is recursive A node's value is Σ of its children's values plus its own sensors. Not a flat sum of every sensor underneath — so when a node corrects itself, every ancestor is right automatically, with nothing to restate further up.
Formulas are overrides A formula lists only what differs from weight 1. Everything unlisted still counts normally, so attaching a sensor always moves the numbers and nothing is silently dropped. ×0 excludes, ×−1 subtracts, ×0.28 apportions.
Formulas can reach sideways Terms may name any sensor in the company, not just ones underneath. That is how a building whose main meter and submeter sit in different buildings gets its own value — see Property C below. Child nodes stay descendants-only, so composition can never loop.
The tree is the company's own Each company defines its own node types. This one runs property → building → area → meter; another might run field → array → sensor. Sensors hang off whatever node that company uses.
Total & unallocated Total is the node's value for that energy type. Unallocated is total minus everything claimed for a purpose, so partial instrumentation shows up as a number instead of disappearing.
Derived rows When a formula's output energy type differs from its sensors' — gas m³ × brændværdi × virkningsgrad, or el × COP — the row is derived. It is delivered energy, not metered consumption, so it never folds into a total.
